Explain evidence in ordinary language (see `evidence-and-claims`): "The protocol
describes...", "I checked...", "This suggests...", without bracketed status
tags. Use numbers from inspected source, tool output or verified saved results,
never from memory; a card status command or an unfinished audit is work status,
not evidence. When a meaning is not in the export (what a treatment is and its
unit, whether a unit or scale is right, whether zeros are real, which of two
disagreeing sources to trust), ask the user with `ask_user` and keep the
question and answer in workspace notes when useful; continue independent work
and explain any conservative assumption. Use the L1 skills for the science:
`phenotyping-onboarding-checks`, `size-and-growth-traits`, `treatment-response`,
`physiology-signals` and `phenotyping-report`.
